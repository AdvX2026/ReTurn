# apps/ReTurn — Agent Notice

- SwiftUI multiplatform Xcode project (deployment targets iOS 17.0 / macOS 14.0), built with Xcode 26. MVP UI implementation and demo verification prioritize iOS/macOS 26. Prefer native OS-26 SwiftUI behavior over hand-drawn approximations; preserve the older deployment targets with small, localized `#available` branches and standard-system fallbacks unless the user explicitly changes the minimum versions. visionOS removed. macOS App Sandbox is OFF per PRD §6.1 (sandbox without outgoing-network entitlement blocks LAN access to Pi/sampler).
- `project.pbxproj` uses synchronized folder groups: any file added under `ReTurn/` / `ReTurnTests/` is picked up automatically — never hand-edit the pbxproj to add files.
- Xcode 26 builds this target as a mergeable library: the ~58 KB `ReTurn` executable is a stub and the real code lives in `ReTurn.app/ReTurn.debug.dylib`. Incremental `xcodebuild build` has silently no-oped over on-disk source changes here and shipped a stale dylib to the simulator — always `xcodebuild clean build` before install-and-verify. `xcodebuild test` runs on a "Clone" device in a separate device set that `xcrun simctl list` cannot see; capture visual evidence via `XCTAttachment` + `xcrun xcresulttool export attachments --path <xcresult> --output-path <dir>` instead of `simctl io screenshot`.

## iOS/macOS 26 UI policy

- Prefer system components that adopt Liquid Glass automatically. For eligible custom navigation/control surfaces, use native APIs such as `glassEffect`, `GlassEffectContainer`, and glass transitions instead of recreating highlights, refraction, glow, or shadows.
- Keep Liquid Glass in the functional navigation/control layer. Plain `Label`, text, symbols, and content backgrounds do not receive glass directly; they use semantic foreground styles inside the glass-bearing control or surface.
- Use `.interactive()` for genuinely interactive custom glass controls. Choose `regular` by default and reserve `clear` for media-rich backgrounds where its contrast requirements are satisfied.
- Do not layer custom highlight, glow, blur, or shadow artwork on top of native Liquid Glass. Older systems may use a simple standard Material fallback, without attempting to perfectly imitate OS 26.

## Models.swift (shared-contract mirror)

- Mirror basis: `origin/feat/global-search` @ `809ec73` (PR #8 — the designated v0.6 API authority; PR #16 was abandoned in its favor). PR #8 is merged to main; keep future `packages/shared` contract changes synchronized here in the same commit (AGENTS.md contract rule).
- Decode/encode ONLY via `ReTurnAPI.makeDecoder()/makeEncoder()` — snake_case conversion lives in the coder strategy; models deliberately have no per-field CodingKeys.
- Enum policy: all mirrored string enums are tolerant (`TolerantEnum`) — unknown raw values decode to a fallback, never throw. Backend keeps growing `NodeKind` (open PRs add `email`, `vscode_recent`, `browse_history`), so strict enums would crash old builds on new server data.
- Card `content` is loose JSON in the contract; the mirror decodes it into typed per-`type` structs (shapes taken from what `services/save.ts` / `services/chat.ts` actually write on the mirror basis) with a `.raw` fallback on unknown type or shape drift. If backend tightens/changes card content, update `BriefingCardContent` & co. and `ModelsTests`.
- IDs and timestamps are plain `String` (server stamps `created_at`; parse display dates via `ReTurnAPI.parseDate`). `client_uuid` is the idempotency key — never regenerate on retry.

## APIClient.swift

- Transport only: typed async methods over URLSession for every Pi endpoint (port 8787). No caching, no outbox, no retries — those belong in the stores (PRD §5.2). LLM-backed calls (save/chat/ask/resume/voice/intent) use a 180 s per-request timeout; plain reads use the URLSession default.
- Health upload sends the fixed token as `x-return-token`. Fastify error bodies (`{statusCode, error, message}`) surface as `APIError.http`.
- Networking config lives in `apps/ReTurn/Info.plist` (deliberately OUTSIDE the synchronized `ReTurn/` folder — inside it, the sync group copies it into Copy Bundle Resources and Xcode warns). It merges with `GENERATE_INFOPLIST_FILE=YES` via `INFOPLIST_FILE=Info.plist` and carries `NSAppTransportSecurity.NSAllowsLocalNetworking` (scoped, NOT arbitrary loads) plus iOS `NSLocalNetworkUsageDescription`. Add future plist keys here, not as INFOPLIST_KEY_ build settings for dict-valued keys.

## Main timeline UI

- macOS has its own product layout (since feat/macos-ui): `ContentView` splits per platform — iOS keeps the horizontal pager, macOS gets `MacRootView`. Desktop layout metrics live in `ReTurnDesign.Desktop`; `MacRootView`/`MacBeforeView`/`MacAfterView`/`MacCalendarView`/`MacDayTimelineView` are `#if os(macOS)`.
- `MacRootView` IS the iOS pager structure: horizontal `ScrollView` + `scrollTargetBehavior(.paging)` + `scrollPosition(id:)`, so trackpad two-finger swipes and Magic Mouse swipes turn pages natively (an earlier NavigationSplitView sidebar and a simulated `.move` transition were both rejected — the sidebar turned a time flow into a document switcher, the transition duplicated what the pager gives for free). Keyboard (←/→ step, Escape returns to Now, ⌘1/2/3 jump), floating window-edge arrows and the clickable top label row all drive the same `scrollPosition` binding; arrow/Escape shortcuts are `.disabled` while the composer is focused so text editing keeps its cursor keys.
- The Timeline layer (models, event views, `TimelineDesignTokens`) is shared by both platforms; `BeforeView`/`TimelineView` are used by iOS only, while macOS `MacBeforeView` is its own browser: `MacCalendarView` (month grid, event dots, locale-first weekday order) + `MacDayTimelineView` (horizontal 24h track: span bars with greedy overlap lanes, sleep lane, input symbol dots, ambient baseline dots, hover `.help` tooltips) + a detail list reusing the shared event views. The track sits in its own horizontal ScrollView and OPENS at `timelineDefaultZoom` (2×) so swiping over it always browses the day — an earlier 1× default made swipes fall through to the pager and users read the browsing as missing. Zoom runs 1…`timelineMaxZoom` (8×) via trackpad pinch or the always-visible −/+ controls (buttons walk discrete steps, the badge resets to default); ticks switch 3h → 1h once an hour is `timelineDenseTickHourWidth` wide. At zoom 1 the track fits exactly and swipes fall through to page turning; nested same-direction scroll chaining handles the handoff. Its width is an explicit parameter (viewport × zoom) measured via `onGeometryChange`, NOT a GeometryReader — the no-GeometryReader rule below guards the iOS pager/composer coupling. Day stepping also has ‹ › header buttons walking recorded dates. TimelineDesign colors carry per-OS branches — named system accents resolve through a `AccentColor` typealias, grouped-background/fill colors have explicit macOS mappings.
- `ComposerBar` lives in its own file, shared by both roots. `AfterCards` (`TodoCard`/`HealthCard`/`IdeaCard`) is the shared After-card layer used by `CardGallery` and the macOS After grid; iOS After remains unimplemented.
- `ContentView` is a horizontal Before / Now / After pager, defaulting to Now. The top navigation and the swipe position share one `TimelinePage` selection.
- That navigation is three plain labels, deliberately **not** a segmented `Picker` — the filled capsule was the only opaque surface on the screen and outweighed the flat mascot and translucent composer around it. Each label lays out at its `.semibold` width with the live text overlaid, so selection weight changes cannot shift the row.
- The row dims to `navigationDimmedOpacity` when idle rather than hiding, so the current page stays readable, the row keeps hinting other pages exist, and the labels stay tappable (opacity does not affect hit testing). Its `.task(id: NavigationActivity(...))` is keyed on both the page and the pager's scroll phase: a non-idle phase holds full strength without counting down, and the countdown starts on the restart that follows the pager going idle. Do not key it on `selectedPage` alone — `scrollPosition` updates when the settle animation *begins*, which is both too late to feel responsive to the drag and too early to measure "settled". `onScrollPhaseChange` is iOS 18 / macOS 15, so it sits behind an availability branch; older systems degrade to waking on the page change. Also note `try? await Task.sleep` swallows cancellation — the `guard !Task.isCancelled` after it is required, or superseded timers dim right after their replacement restored full strength.
- The initial Now visual follows Figma file `ilZuF3hqB1HH7f1usiMmPM`, node `7:1182`. Shared HIG colors, spacing, semantic typography, and adaptive layout rules live in `DesignTokens.swift`; do not scatter replacement literals through views.
- The Before page is mounted with `TimelinePreviewData.days` on both platforms until an API-backed timeline store exists. Keep the fixture isolated as visual/demo data rather than treating it as persisted state; After is fixture-backed on macOS and unimplemented on iOS.
- Timeline chrome uses the available container width with compact-screen insets and readable iPad caps. The composer expands with a spring animation while focused and grows vertically from one to five text lines before scrolling internally; preserve this responsive behavior instead of restoring device-specific widths or a single-line field.
- On iOS/macOS 26, the composer surface uses the native interactive `glassEffect`; do not add manual highlight, glow, or shadow overlays on top. Older systems retain the standard Material fallback.
- `Kongkong.imageset` is the exact vector exported by Figma (`preserves-vector-representation`), so it re-rasterizes on every new size. Keep the asset rather than redrawing the mascot in SwiftUI, and keep its width sourced from the scroll viewport — never from a container size that the keyboard or the composer animation can change. The one sanctioned redraw is `MascotView` (see below): it reproduces the Figma geometry verbatim as layered Canvas shapes so it can animate — do not approximate the silhouette a third way.

## Now mascot (MascotView)

- The Now page uses `MascotView`, a layered Canvas reproduction of the Figma geometry (body/arms/legs/eyes separate so they can animate: squash-and-stretch bounce, blink, arm wave, tap-to-hop). Cards keep the static `MascotImage` asset.
- Stat mapping (values 0–100, colours from `ReTurnDesign.Colors.Accents`), Binding-of-Isaac principle — state reads on the body itself: intake → sparkles spiral inward and are absorbed (count/pace); focus → star glints in the eyes, and pupils wander when low; output → spinning gear by the right hand plus sweat drops flung off the flanks above 50; continuity → comet dots with fading trails on the orbit ring; energy → the face itself (smile vs tired frown, hooded eyelids below ~45) plus bounce amplitude/tempo and aura glow.
- Worn profession accessories (glasses/pencil/beret/bow tie) draw inside the body's squash transform so they deform with it; the researcher's magnifier floats outside it, handle ending at the waving right hand so it reads as held. The writer's pencil is gripped in the raised left fist: `MascotAccessory.drawWorn` takes the left arm's pivot and live angle, and the pencil draws in that rotated local frame (plus 15° about the grip point) so it swings with the arm. `MascotProfession` (coder/writer/designer/researcher/manager) is client-provisional — replace with the contract field (prd-drift §C, `TolerantEnum` in `Models.swift`) when it lands.
- All mascot drawing lives in ONE coordinate space: the SVG's own 175×150. The Canvas applies a single stage transform up front (`translateBy(pad*unit)` → `scaleBy(unit)`), so every constant in `MascotView`/`MascotAccessories` is a verbatim Figma number — never mix in a second padded space. Pivot animations use `translateBy → scaleBy/rotateBy → translateBy(-)` only (these pre-concatenate); `concatenate(_:)` post-multiplies and silently breaks pivots, and `rotate(by:)` takes an `Angle` (`.radians(...)`), not a `Double`.
- `TimelineView` must be spelled `SwiftUI.TimelineView` anywhere the app's own `TimelineView` (Before timeline) is visible, or the compiler picks the app type.
- The Now page runs a demo driver until an API-backed Now store exists: every 3 s it advances to the next profession, with one stat pushed to 95 (rest at 40) so each wearable takes a turn in the spotlight; the label reads "Profession · stat". `MascotView(stats: nil)` renders the plain mascot. The macOS `MacNowPage` still shows the static `MascotImage`; swapping it for `MascotView` is a follow-up.
- `MascotView(walking: true)` swaps the idle bounce for a stride: fixed cadence (`Motion.walkCadence`) instead of the energy-driven tempo, legs stepping alternately around the hip, arms counter-swinging, and a constant 4° forward lean — the caller flips the view horizontally (`scaleEffect(x: -1)`) to turn the figure at each end. `ContentView.ComposerWalker` uses it: while the composer is focused, a small plain coder paces a strip above the composer (~110 pt/s triangular wave over the full width, inside the safeAreaInset VStack, `stats: nil`). Covered by `ReTurnUITests.testComposerWalkerAppearsWhileTyping`, which also attaches three pacing frames to the xcresult for visual review (test clones are invisible to `simctl`, so `XCTAttachment` is the capture path — see the mergeable-library bullet above).
- `ContentView` / `NowPage` / `ComposerBar` are deliberately separate views and the screen uses **no `GeometryReader` around the pager** (the ComposerWalker's small strip reader is the sanctioned exception — it measures only the pacing strip). `ComposerBar` owns the draft text so typing cannot invalidate the pager; adaptive widths are `.frame(maxWidth:)` + `.padding(.horizontal:)` and page frames are `.containerRelativeFrame`. Reintroducing a `GeometryReader` around the pager re-couples the composer's spring animation to a full pager relayout on every frame.
- The composer's attachment `Menu` is a single control inside the glass content layer; `.buttonStyle(.plain)` suppresses the bordered pressed state the system otherwise draws around the glyph. Its touch target reaches the 44pt minimum via `padding(hitPadding)` → `contentShape(.rect)` → `padding(-hitPadding)`; never clip it to the glyph bounds (`clipShape`/`contentShape` around a `.title2` symbol yields a ~20pt target, and `clipShape` clips hit testing too).
- Opening the attachment menu merges the composer's `glassEffect` surface into the menu, so the input field is not visible while the menu is open. **This is accepted behavior, not a bug — do not "fix" it.** It is iOS 26's Liquid Glass presentation language (the menu grows out of its source surface), and the user chose to keep it rather than fight it.
- Should that decision ever be revisited, these are already ruled out: `.buttonStyle(.plain)` (removes the pressed box, not the merge); a UIKit `UIButton` + palette `UIMenu` via `UIViewRepresentable` (tried and reverted in e2022be — UIKit presentation merges too); a transparent second `Menu` layered outside the glass (avoids the merge, but the two-layer structure was rejected as inelegant). Untried: `GlassEffectContainer` + `glassEffectUnion` to give the plus its own morph identity, or a self-drawn panel — which is how ChatGPT's iOS app does it (its attachment sheet is not a system menu: circular icon backings, leading icons and ~40pt corners are all outside what `UIMenu` renders).
- The iOS composer needs its own `contentShape` + tap-to-focus: the `TextField` only covers one text line, so the surface's vertical padding is otherwise dead and taps there do not raise the keyboard.

## Before timeline

- Timeline is the detail/index layer; Product Cards are the summary layer. A white Timeline Cluster remains a time-bound, drill-down timeline segment and is not a `CardType`. Do not flatten either layer into the other or apply Liquid Glass to timeline content.
- Explicit Input points are currently limited to `text`, `url`, `voice`, and `image`. Preserve their two-line Point presentation, native 44pt `Button`, full VoiceOver value, and lack of card surface or disclosure chevron. `save_note` and unprovenanced `idea` are deliberately not classified as Input.
- A historical Daily Briefing is a one-line date-header entry, has no rail node, and does not contribute to Event count. Its stable destination is the briefing `CardRecord.id`; the full Card Group belongs on a separate history page.
- Current `TimelineDisplayItem` salience and cluster projection are preview/MVP heuristics, not shared-contract authority. Stable item identity, provenance, cluster children, and typed destinations still require a separate contract review before changing `packages/shared` or `Models.swift`.
