# ReTurn PRD（临时代号）

> 版本：v0.3 · 2026-07-23 · 黑客松 48h 范围
> 一句话：一个"每日存档"式的本地第二大脑桌面应用——白天随手投喂信息，下班时像经营游戏一样 Save Today，第二天 Continue Yesterday 领取昨日发酵出的开场白和待办。

---

## 1. 产品概述

- **形态**：macOS 桌面应用（Tauri 2）。
- **核心隐喻**：把每一天当作一局经营游戏的存档。信息收集不再是"整理负担"，而是"经营积累"。
- **目标用户**：知识工作者/学生，信息来源分散（网页、语音、灵感碎片），缺乏每日复盘习惯。
- **黑客松交付目标**：48 小时内做出**假数据尽量少、可完整演示运行**的产品。

### 1.1 评委叙事（Pitch）

- **痛点**：收藏夹吃灰、笔记软件成了信息坟场。复盘有价值，但没人坚持得下来——因为它是负担。
- **差异**：Rewind / Mem / Obsidian 这类工具比拼"更强的记录与搜索"；ReTurn 比拼"让你愿意每天回来"。把复盘从负担变成仪式：下班存档、次日读档，像经营游戏一样看着自己的空间长大。
- **一句话**：第二大脑工具解决"存进去"，ReTurn 解决"第二天还想打开"。

## 2. 核心循环（Day Loop）

```
白天                下班时                夜间(即时)             第二天早上
随手投喂  ────────▶  Save Today  ────────▶  AI 发酵  ────────▶  Continue Yesterday
文本/链接/语音       环境快照+当日节点打包    总结/连边/属性结算      昨日一句话 + 今日待办
```

1. **投喂（全天随时）**：用户丢入文本片段、URL、语音（云端转写为文本）。每次投喂生成一个**节点**。
2. **Save Today（一天一次，手动触发）**：
   - 抓取**环境快照**：当前运行的应用列表、浏览器打开的标签页（标题+URL）。快照内容同样落为节点。
   - 将当日全部节点打包送 LLM"发酵"：生成当日总结、提取主题、在新旧节点间建边、结算角色属性。
3. **Continue Yesterday（次日首次打开时）**：
   - 展示昨日发酵结果：**一句话开场白**（基于昨日内容的洞察/鼓励）+ **今日 todolist**（从昨日未竟事项和标签页推断）。
   - 展示成长视觉的变化（见 §4）。

## 3. 功能需求

### P0 — 演示主线，必须完成

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 快速投喂框 | 全局常驻输入：文本直接存；URL 抓取页面标题+正文摘要；语音按住录音→云端转写 |
| F2 | 环境快照 | Save Today 时抓取：运行中应用列表 + Chrome/Safari 标签页（AppleScript）。快照条目与投喂内容同为节点 |
| F3 | Save Today 发酵 | 一次 LLM pipeline：当日总结（200 字内）、节点主题标签、新旧节点连边（图存 SQLite）。属性不经 LLM，由代码确定性结算（见 §4） |
| F4 | Continue Yesterday | 次日打开展示：昨日一句话 + 今日 todolist（可勾选，勾选记为当日节点） |
| F5 | 成长视觉 + 属性面板 | 一个随存档天数/质量成长的视觉主体（树/山，二选一，见文末待定项）+ 属性参数表（如：专注、摄取、产出、连贯） |
| F6 | 当日节点流 | 时间线列出今日已投喂/已抓取的节点，可删除（错误抓取的兜底） |
| F7 | 状态一览 | 近 7/30 天视图：属性趋势折线 + 存档热力格（GitHub contribution 风格）+ 点某天可看当日总结。数据全部来自 `days.stats_json`，无新增采集 |
| F8 | 存档结算画面 | Save Today 后的"每日结算"：属性数值逐项跳出、连击（streak）展示、成长物生长动画。它是本产品最像游戏的一刻，动效资源优先投入；同时天然掩护发酵的 LLM 等待时间（10~30s） |

### P1 — 有余力再做

- 剪贴板监听（复制即候选节点，需用户确认收录）。
- 对空间提问（简单 RAG：取相关节点塞 prompt 回答）。
- T1 档软件接入（见 §3.1：Git 提交、VS Code 最近项目、Chrome 当日历史）。

### P2 — 明确不做（黑客松内）

- 知识图谱可视化界面（图只作为内部数据结构）。
- 任意应用窗口标题/内容抓取（权限与工程量，见文末）。
- 任何形式的插件/扩展开发（VS Code 扩展、Chrome extension、WakaTime 类心跳上报）。
- 多用户、同步、移动端。

### 3.1 软件接入（采集源清单）

原则：**只读软件留在磁盘上的痕迹**（本地文件、AppleScript），不写插件、不逆向私有 API。按 48h 可行性与信号价值分档：

| 档 | 来源 | 取什么 | 怎么取 | 成本 |
|---|---|---|---|---|
| T0（=F2，必做） | Chrome / Safari | 当前打开的标签页（标题+URL） | AppleScript，一次自动化授权 | 低 |
| T0（=F2，必做） | 系统 | 运行中应用列表 | `osascript` / NSWorkspace | 低 |
| T1（P1，按序捞） | Git | 本地仓库当日提交（message、改动文件数） | 用户配置代码目录，扫描 `git log --since` | 低，"产出"属性最硬的信号 |
| T1 | VS Code | 最近打开的项目/文件 | 读 `state.vscdb`（本地 SQLite） | 低 |
| T1 | Chrome | 当日浏览历史 | 拷贝 `History` SQLite 后读（原文件被 Chrome 锁定） | 中，比标签页快照信息量大 |
| T2（黑客松后） | 日历 | 当日日程 | AppleScript 读 Calendar | 中 |
| T2 | Obsidian / 本地笔记 | 当日修改的 markdown | 文件系统扫描 mtime | 低，但受众有限 |
| T2 | Spotify / Apple Music | 当日听歌氛围 | AppleScript now-playing 轮询 | 低，纯演示情绪价值 |

采集到的条目一律落为 node（`kind` 相应扩展：`git_commit`、`vscode_recent`、`browse_history` 等），进入同一发酵管线。

## 4. 成长与激励（游戏层）

- **视觉主体**：单一成长物（森林式种树 或 登山进度，待定），每次 Save Today 推进一步；连续存档有可见的连击感（streak）。
- **属性参数表**：4 项，**全部由代码从库内事实确定性计算，LLM 不打分**——可解释、可复现，演示时数值不会无故跳变：
  - 摄取 = 当日节点数 × 来源种类数（加权）
  - 专注 = 当日节点主题标签的集中度（标签由 LLM 标注，聚合计算在代码）
  - 产出 = todolist 完成率（+ 接入 Git 后叠加当日提交数）
  - 连贯 = 本次发酵新增的跨日连边数
- LLM 只负责文本产物：当日总结、明日开场白、todolist、连边判断。
- 属性只做展示与视觉反馈，**不做惩罚机制**（48h 内避免负反馈调参）。

## 5. 数据模型（SQLite）

```sql
nodes(id, day_id, kind, title, content, source_meta, created_at)
  -- kind: text | url | voice | app_snapshot | tab_snapshot | todo
edges(id, src_node_id, dst_node_id, relation, created_by_day_id)
days(id, date, saved_at, summary, opening_line, stats_json)  -- stats_json = 属性结算
todos(id, day_id, text, done, source_node_id)
```

- 一切收集物统一为 node；"存档"= 给当天的 nodes 盖章（saved_at）并生成 day 级产物。
- 语义检索（P1 提问功能）：小数据量直接在 TS 内算 embedding 余弦相似度，不引入向量库。

## 6. 技术架构

| 层 | 选型 | 备注 |
|---|---|---|
| 桌面框架 | Tauri 2 | |
| 前端 | React + TypeScript + Vite | 业务逻辑尽量放 TS 侧 |
| 状态 | Zustand | |
| 校验 | Zod | LLM 返回的 JSON 一律 Zod 校验 + 一次重试 |
| 样式 | Tailwind CSS | |
| Rust 层 | 保持薄 | 仅：SQLite 访问（tauri-plugin-sql）、环境快照命令（调 osascript）、录音文件落盘 |
| AI | OpenAI-compatible 云端 API | 对话/总结/发酵 + 语音转写（Whisper 兼容接口）。key 走环境变量/本地配置，不入库不入 git |

**发酵 pipeline 设计原则**：
- 一次 Save Today = 1~2 个 LLM 调用（一个大 prompt 输出结构化 JSON：总结/标签/连边/明日开场白+todolist），避免逐节点调用导致演示时等待过长。属性数值不在 LLM 输出中，由代码在发酵落库后结算。
- 所有 LLM 调用带超时 + 一次重试；发酵失败时降级回放上一次已落库的真实结果（不阻塞存档主流程）。
- 发酵输出的 JSON schema 是前端、prompt、数据层三方的合同，T+6h 冻结（见 §8）。

## 7. 演示脚本（3 分钟）

1. 早上打开 app → Continue Yesterday：昨日一句话 + 今日待办（提前真实存档过一天，非假数据）。
2. 现场投喂：打几个字、贴一个链接、录一句语音（现场转写）。
3. 现场 Save Today：环境快照动画（展示抓到的真实标签页）→ 结算画面（F8）：属性逐项跳出、成长物长一格（动画同时掩护发酵等待）。
4. 切到状态一览：展示开发期间攒下的几天真实趋势和存档热力格。
5. 收尾：翻看当日节点流，展示"环境+灵感都成为同一空间的节点"。

## 8. 里程碑（48h）

- **T+2h**：三个 spike 全部验证通过，跑不通的当场砍或换方案：① AppleScript 读浏览器标签页的授权流程；② Tauri webview 内录音权限（`getUserMedia`）；③ 云端 API 连通与转写。
- **T+6h**：发酵 JSON schema 冻结（前端 / prompt / 数据层三方合同）。
- **T+12h**：数据层 + 投喂（文本/URL）+ 节点流可用。
- **T+24h**：Save Today 全链路（快照+发酵+落库）跑通。
- **T+36h**：Continue Yesterday + 结算画面 + 成长视觉 + 属性面板 + 状态一览。
- **T+44h**：功能冻结（语音投喂、动效打磨在此之前完成）。
- **T+44~48h**：全队真实使用攒演示数据、排练、录备用演示视频。

## 9. 待定项与不完善之处（需讨论）

1. **【砍功能，需确认】"深度环境快照"降级为：运行应用列表 + 浏览器标签页。** 抓任意应用窗口标题需要 macOS 屏幕录制/辅助功能权限，且各应用行为不一，48h 内风险过高。浏览器标签页（AppleScript 读 Chrome/Safari）只需一次自动化授权，已能支撑"存档当前环境"的演示效果。
2. **成长视觉未定（树 vs 山 vs 像素小人）**：影响美术资产与动效工作量，建议第 0 小时定死。倾向"单一成长物 + 属性面板"，比像素小人省美术且激励表达同样清晰。
3. **概念张力：快照是"瞬间"，投喂是"内容"**。统一为节点后，快照类节点（如"打开着 12 个标签页"）信息密度低，可能稀释发酵质量。缓解：发酵 prompt 中把快照作为"上下文"而非"知识"处理。
4. **隐私矛盾**：环境快照（你开着什么网页）会被送云端 API 发酵——与"第二大脑属于自己"的叙事相悖。演示可接受，但答辩时若被问及，需有说法（如：路线图上支持本地模型）。
5. **"第二大脑"的取出端很弱**：图谱不可视化、又没有搜索/问答（仅 P1），演示中"空间在积累"主要靠属性和总结体现，说服力可能不足。若时间富余，P1 的"对空间提问"是最值得捞回的一项。
6. **todolist 生成质量不可控**：从标签页和碎片推断待办容易生成废话。缓解：允许用户在 Save Today 时补一句"明天想干嘛"，作为生成锚点。
7. **冷启动**：第一天没有"昨日"，Continue Yesterday 无内容。演示已绕开（提前存档一天），但产品上首日流程需要一个简单的引导态。
8. **状态一览依赖多天数据**：48h 内真实数据最多两三天，趋势图会很空。缓解：从开发第一天起全队每人每天真实 Save Today，用真数据攒图；不造假数据。
9. **图表库是新增依赖**：状态一览需要一个轻量图表方案（候选 Recharts；或热力格+折线直接手写 SVG，省一个依赖）。引入前需确认。
10. **现场网络是最大演示风险**：工程侧兜底已列入 §6（超时、重试、失败回放已落库真实结果）；演示保障（手机热点、备用演示视频、演示脚本兜底）**由设计侧负责落地**。
